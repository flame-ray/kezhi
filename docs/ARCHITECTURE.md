# 课织架构草案

## 核心目标

课织的界面不理解任何具体教务系统。所有学校数据在进入界面前必须转换为统一的 `CourseMeeting`、`TimetablePreset` 和学期模型。这保证学校页面变化只影响对应适配器。

## 模块与接口

### 课表核心模块

接口位于 `src/domain/schedule.ts` 和 `src/domain/scheduleEngine.ts`。调用方只需要提供统一课程、学期开始日期和周次，即可获得七天 `WeekView`。单双周过滤、排序、移动和以后加入的冲突计算都隐藏在这个模块中。

### 学校导入模块

学校适配器在同一个流程下完成：

1. 判断当前登录状态。
2. 列出可用学期。
3. 获取原始课表。
4. 解析教师、教室、节次和周次。
5. 输出统一导入快照与警告列表。

当前宁德师范学院适配器已经实现完整链路。`src-tauri/src/lib.rs` 创建按“学校 + 账号”隔离的 WebView2 登录窗口，并在原生层使用会话访问固定的学校课表接口；Cookie 值和学生资料不会返回 React。`src/importing/zhengfangAdapter.ts` 将 `kbList` 转换成统一课程模型，并报告无法识别的记录。

`src/importing/schoolCatalog.ts` 只保存学校发现信息，不包含登录凭据。`ImportWizard` 负责用户确认流程，但不会持有学校密码。真实账号的端到端验收、接口变化探测和其他学校适配仍需继续完成。

### 本地存储模块

SQLite 模块位于 `src-tauri/src/database.rs`，其 interface 只提供加载/保存课表快照和加载/保存账号档案。实现内部使用课程、作息方案、节次、全局状态和账号档案的规范化表，并在单个事务内替换完整快照。内存 SQLite 是该本地依赖的测试替身，测试通过同一 interface 验证往返、事务替换和输入校验。

原生版首次启动会读取 SQLite；数据库尚无数据时，React 将旧 `localStorage` 快照作为迁移输入。后续保存使用防抖事务。数据库不保存密码或 Cookie，学校登录会话继续由 WebView2 的 Windows 用户数据目录管理。

### 插件宿主（开放平台阶段）

插件只通过权限化接口访问数据，不直接读取数据库或浏览器配置目录。成绩、身份信息、网络和后台运行属于单独权限。插件崩溃必须与主窗口隔离。

## 同步不变量

- 教务数据不能静默覆盖本地修改。
- 每次同步先生成差异，再应用用户的合并策略。
- 每个学校账号使用独立 WebView2 数据目录。
- 日志中禁止出现密码、Cookie、令牌、姓名和完整学号。
- 退出账号时只清除该账号的会话，不影响其他账号。

同步差异的 seam 位于 `src/sync/scheduleSync.ts`。它是纯计算的深模块：调用方只使用 `createScheduleSyncPlan` 生成变化计划，再使用 `applyScheduleSyncPlan` 应用用户选择；课程配对、相似度匹配、字段比较、手动课程保护和增删改合并都隐藏在实现内部。学校适配器或同步界面均不重复这些规则。

启动同步会创建不可见的 WebView2 窗口并访问学校首页来验证已有会话。有效会话继续读取课表；失效会话在后台保持静默，用户主动同步时才进入重新登录流程。自动检查只生成差异计划，不静默覆盖课程。

## 性能约束

- 课表切换和拖动只更新受影响的课程与日期列。
- 动画优先使用 `transform` 与 `opacity`。
- 60Hz 屏幕必须稳定达到 60 FPS，高刷新率屏幕跟随系统刷新率。
- 低性能和节能模式允许降低模糊、阴影与过渡效果。
- 尊重 `prefers-reduced-motion` 与 Windows 减少动画设置。

## 一键启动与导出

`启动课织.cmd` 是 Windows 双击入口：优先启动 Release EXE，没有成品时进入 Tauri 开发模式。`scripts/start.ts` 仍保留为纯浏览器预览入口，其服务只监听 `127.0.0.1`，不会暴露到局域网；浏览器预览不具备学校会话能力。

`src/exporting/scheduleExport.ts` 是纯本地导出模块：ICS、CSV、JSON 和 SVG 都由内存中的统一课表模型生成，不上传数据。打印/PDF 使用 Windows 浏览器打印面板。
