# 自动选课代码审计（0.4.2）

审计日期：2026-09-08

本轮没有向任何学校服务器发送登录、查询或选课请求。结论来自源码审查、前端测试、Rust 测试以及 Windows/Android 发行构建。

## 本轮已处理

- Windows 使用 Credential Manager 保存账号密码；Android 使用 Keystore AES-GCM。
- 前端只有保存、状态查询、删除接口，不提供读取明文密码的命令。
- 官方登录页自动填充账号密码，但不自动点击登录。
- 请求学习器会跳过带密码输入框的页面、常见登录路径和包含密码字段的请求体，避免 AJAX 登录凭据进入学习快照。
- 修正 3 处过期的 Rust 测试调用参数；生产选课提交逻辑未因此改变。
- 后续全量体检已修正 JSON 成功标志覆盖验证码/满员等失败消息的问题。
- 多门候选课改为循环公平取批，不提高并发数和请求频率。
- GET 模板参数现在会合并到查询字符串。
- 立即试跑明确标注会真实提交，且不会持久部署；所有运行结束后自动解除部署。
- 移除渲染线程最后 40 毫秒忙等，避免选课页面必然丢帧。

## 待处理问题

### P1：原生层没有证明提交地址来自学习记录

`checked_portal_endpoint(..., true)` 只校验同域 HTTPS，并按路径黑名单拒绝少量词语。前端仍可把同域的其他写接口传给原生提交层，因此“必须来自学习记录”的注释目前不是强制不变量。建议由原生层签发短期学习令牌，绑定账号、来源页面、方法、地址和模板摘要，提交时强制核验。

### 已修复：JSON 真值字段可能覆盖失败消息

响应分类先把 `success`、`flag`、`result` 等真值直接判定为成功，之后才分析消息。类似 `{ "success": true, "msg": "人数已满" }` 会被误报为成功。建议先识别验证码、登录失效、未开放、已满和重复，再把明确成功字段作为最后的正向证据，并增加冲突响应测试。

### P1：HTTP Date 不能提供真正的毫秒级校时

当前校时只读取标准 HTTP `Date` 响应头；该时间通常只有秒级精度。即使计算和 UI 使用毫秒，也不能据此保证毫秒级触发。建议优先学习学校提供的毫秒时间接口；否则显示误差范围，不宣称毫秒级校准。

### 已修复：GET 模板的参数不会发送

界面允许把模板方法设为 GET，但原生层在 GET 分支忽略 `bodyTemplate`，不会将其编码进查询字符串。建议禁用 GET 提交模板，或把模板作为查询参数合并进 URL。

### P2：学习器没有完整记录请求形态

学习器目前只记录字符串请求体和 `Content-Type`。`FormData`、`URLSearchParams`、`Request` 对象、CSRF 头及 `X-Requested-With` 等不会被完整重放，通用学校兼容性会受到影响。应按允许列表记录必要头，并为常见请求体类型做结构化序列化；敏感字段必须继续过滤。

### 已修复：多目标可能饥饿

每轮总是从待处理列表头部取 `concurrency` 个目标。前面的目标持续重试时，后面的目标只能等它们成功或耗尽次数。建议使用循环游标或公平队列，并增加 4 个以上目标、并发小于目标数的测试。

### P2：停止操作不能取消在途提交

`stop()` 只唤醒等待计时器。已经发给原生层的请求仍可能完成，所以点击停止后最多还有当前并发数个提交到达服务器。建议为每轮分配取消令牌，并在传输层支持中断或至少忽略过期轮次的后续状态变更。

### P3：Referer 固定为登录页

原生查询和提交把登录 URL 作为 `Referer`，不是实际学习到的选课页。启用来源校验的教务系统可能拒绝请求。建议把经过同域校验的学习页 URL 绑定进模板。

### 已修复：最后 40 ms 忙等会阻塞界面线程

执行器在渲染线程忙等最后 40 ms，必然丢失约 2～3 帧动画。建议把精确定时迁到 Rust/Android 原生后台线程，同时让界面只订阅状态。

## 验证结果

- `npm test -- --run`：18 个测试文件、87 项测试全部通过，其中自动选课 18 项。
- `npm run build`：通过。
- `cargo test`：14 项全部通过。
- `cargo check`：通过。
- Android arm64 Release APK：通过编译并完成 v2/v3 签名验证。
- Windows x64 NSIS：通过构建。

现有自动选课核心 TypeScript 文件已与修改前备份做 SHA-256 对比，保持不变；本轮只在原生网页登录采集层加入凭据过滤保护。
