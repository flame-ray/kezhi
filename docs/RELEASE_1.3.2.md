# 1.3.2 — 拉伸重排与全天课表

本次发布 Android arm64 正式签名安装包与源码。Windows 继续使用 [v1.3.0 安装包](https://github.com/flame-ray/kezhi/releases/tag/v1.3.0)，教务登录、选课等功能不改动。下载 `Kezhi-1.3.2-arm64.apk`（约 22.6 MB），可覆盖安装同签名正式版；安装前建议导出课表备份。

## 修复拉大后仍是小卡片

- 不再把固定的五档尺寸映射交给桌面自行挑选，改为读取尺寸回调，明确生成当前横／竖屏布局。这样桌面即使通过不带尺寸的旧式 RemoteViews 接口加载，也不会回退到最小模板。
- 回调保存尺寸快照，并合并可能缺失的选项，避免异步更新时重新读到旧尺寸。
- 每次尺寸变动完整更新该组件，缩小时也重新选择简洁卡片。

已用原生 RemoteViews 的无尺寸加载复现旧映射选中小模板，并验证新版大／小／窄长／两列宽多次切换。没有连接用户的小米真机，不能声称已复现并解决其桌面的所有厂商行为。

## 全天连续排版

- 高度达到 260dp：一格窄条与两格宽卡片转为全天课表；宽面板在高度达到 300dp 后转为全天布局。格数随桌面网格变化，并非硬编码列数。
- 一格宽：起止时间上下放，课程和教室换行。
- 两格宽：起止时间并排，课程和教室纵向排列。
- 宽面板：左侧时间、右侧课程／教室，正在上课的条目突出显示。
- 保留今天已结束的课程，不再默认跳到下一堂所在页，也不再每三堂分页。
- 空间足够时一次展示全天；用原生文字测量决定排版密度，不用省略号截掉名称。遇到特别多的课程、很长的名称或大字体，连续滚动查看全部，不能在有限面积里无限缩小文字。
- 不再只展示前 30 堂：最多 30 堂使用静态布局测量，更多或放不下时采用受系统权限保护的本地 RemoteViewsService 列表，不一次把大量行打进 Binder。

## 验证与验收

前端 227 项、Android 原生 26 项测试通过，Android arm64 Release 构建和 v2/v3 签名验证通过；沿用原正式签名，版本 1.3.2 / versionCode 10302。安装包 22,600,505 字节，SHA-256：`b64dbd29204aa7279dd68361004291eb1abe6f8db7e71ef8f793df9252983a3e`。

覆盖原生加载、Binder 序列化、反复拉伸、旧尺寸覆盖、大字体、深色主题，以及超过 30 堂课程完整加载和数据清空。原生 Canvas 预览在 `src-tauri/gen/android/app/build/reports/widget-previews-1.3.2/`，使用虚构课程。

测试中的 57×550dp 可完整展示 3 堂，130×600dp / 350×550dp 可完整展示 7 堂。实际能放多少取决于课程名称长度、字体与桌面可用尺寸，不固定承诺某一格数。

安装后先进入课织同步课表，再回到桌面拉伸。若桌面保留了旧布局缓存，可移除该小组件重新添加；这不会删除应用里的课表。请在小米桌面验证反复缩放、横竖屏、滚动、点击打开以及升级后既有组件刷新。

实现参考：[Android 小组件布局与尺寸回调](https://developer.android.com/develop/ui/views/appwidgets/layouts)、[RemoteViews 无尺寸加载回退行为](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/widget/RemoteViews.java)。
